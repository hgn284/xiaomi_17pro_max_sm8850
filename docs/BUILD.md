# 构建说明

## 输入

**发布附件上传尚未完成：完整源码归档目前不能从 GitHub 下载。构建入口已整理，但自动获取依赖仍被此项阻塞。**

- Linux x86_64宿主机、Python3.12、git、make、bc、bison、flex、libelf/libssl/zlib开发包；建议16GB以上内存和充足临时磁盘。
- `manifest/source.json` 锁定的完整9838源码快照（kernel + 原样BakaSU源码，不含构建缓存）。
- `manifest/toolchains.json` 锁定的AOSP Clang19、Rust1.82及构建工具。
- `config/os44.config`、公开模块签名证书、受保护模块名和符号清单。
- `lib/btf/` 中原厂类型元数据及已冻结模块引用集合。**不是原厂驱动二进制，也不是签名私钥。**

## 本地

```sh
bash local/builder_6.12.69.sh
```

脚本下载源码／工具链，然后以独立 `work/out/` 编译。输出放在 `dist/`。原有设备模块仍来自原厂固件；不要把构建生成的通用模块覆盖到手机原厂分区。

每次执行会将 `work/out/.config` 恢复为本项目冻结配置；如需个人修改，请先保存另一个配置副本。失败构建保留 `dist/build.log` 和阶段返回码，不会把旧 Image 作为新产物上传。

`local/build.py` 是既有本地成功构建命令的便携化入口；BTF步骤对本次编译结果重新计算类型图匹配和元数据布局，不能复用旧native映射。原厂模块引用集合来自已冻结元数据，不冒充本轮逐模块运行检查。真实类型、版本和编译失败会使命令失败。

## GitHub Actions

工作流仅 `workflow_dispatch` 手动触发。默认2个并发编译任务，产物为Image及构建信息，不自动出新的刷机包、不自动创建Release。

**首次公开时没有运行云端构建或新测试。** 9838既有成功构建是独立源码副本上的增量编译＋重新链接，不是此次新进行的清洁构建。便携入口首次执行可能暴露宿主环境差异；失败日志应保留，不应删检查、复制CRC或伪造成功。

`zram_patch/next/` 的容量改动尚未接入启动／安装时序，不会被当前builder偷偷加入。它需要下次正式出包前完成早期无损覆盖；把配置放入ZIP不等于手机已采用。
